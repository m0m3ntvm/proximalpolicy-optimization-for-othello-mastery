# Trajectory-MAE warm start vs random init — RTX 5090 A/B

**Date:** 2026-11-25 · **Machine:** Vast.ai RTX 5090 (16 vCPU, 30 GB RAM) · **Code:** commit `0c9b284` (MAE v2 masking), `8b113e9` (trajectory MAE + shared encoder)
**Question:** what is the *isolated* contribution of the masked-autoencoder warm start to PPO training? Same PPO budget, same seeds, same eval protocol — the only difference is the initial weights.

## Pretraining (MAE v2)

| | |
|---|---|
| Data | 100k chunks × 16 consecutive frames from random-play games (`generate_ssl_chunks.py`); per-frame outcome ±1 from the mover's perspective; draws skipped |
| Masking | per chunk, each 4×4 quarter-block dropped with p = 0.5 **tube-wise** (same quarters masked in all 16 frames — adjacent near-duplicate frames can't leak the answer; ~1/16 chunks fully masked, others partially/untouched); last 3 frames fully masked |
| Model | OthelloRL encoder (128 ch × 16 residual blocks, shared policy/value trunk) + small 3D-conv decoder |
| Aux losses | legality CE on the policy head (uniform-over-legal target), value MSE on game outcomes |
| Schedule | 6 epochs, batch 64, AdamW lr 1e-3 · **~25 min on the 5090** |
| Result | masked-cell recon 74.2 → 78.7 % (val), fully-masked future-frame recon 69.0 → 71.3 %, top-move-legal ~95 % |
| Checkpoint | `checkpoints/mae_v2_128x16.pth` (encoder state_dict incl. policy head + shared value head) |

## A/B protocol

- Architecture 128×16, **8192 games/step**, seed 42, PPO defaults (lr 5e-5, clip 0.2, entropy 0.09, value coef 0.5), **25 steps per arm** (≈205k games/arm).
- Eval every 5 steps, `TEST_NUM=600`: 600 games vs random + 600 vs the arm's own best snapshot + 300 vs the depth-3 minimax engine (`EVAL_WORKERS=16`).
- Arm A: `--init-path checkpoints/mae_v2_128x16.pth` → `runs/abv2_mae` · Arm B: random init → `runs/abv2_rand`.
- Caveats: arm A was originally scheduled for 50 steps and cut to 25 mid-run (user decision); it was also interrupted once by a host reboot and resumed from its step-12 checkpoint (optimizer + scheduler state included). Arm A's step-25 round was killed mid-eval by the watcher, so its final vs-best leg is missing. The vs-best legs aren't cross-arm comparable anyway (each arm's "best" is its own init snapshot).

## Interpretation

1. **MAE init beats random init at every rung of every ladder.** Final gaps: **+16.2 pts vs random** (79.1 vs 62.9) and **+13.6 pts vs the engine** (47.3 vs 33.7). With n = 600, one game ≈ 2.0 % (σ at 50 %), so the vs-random gap is **~8σ**; at n = 300 the vs-engine gap is ~4.7σ. This is not noise.
2. **The random arm plateaued** at ~63 % vs random from step 15 on, while the MAE arm was still climbing at step 25 — the curves have not converged; the gap is still growing.
3. **The warm start is worth ~20 RL steps of the 25-step budget:** MAE step-5 (72.3) already clears random step-25 (62.9), and the random arm's plateau (with its LR decayed 8× over the schedule) suggests it would need far more than 25 steps to reach MAE's step-25 level.
4. **Cost is negligible relative to what it buys.** The MAE phase is ~25 min of one 5090, and MAE frames are ~10⁴× cheaper than RL frames (no credit assignment, dense per-cell labels). If RL steps scale with the size of the trainable policy, pretraining the trunk cheaply and letting PPO polish only the heads is the obvious lever — which is exactly the alternating MAE↔RL loop this experiment motivates.
